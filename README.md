# QQ Agent · 刷 B 站 v1.1.4

按当前人格逛 B 站：批量初筛 → 逐条审核字幕与 B 站原生抽帧拼图 → 全部审核完成后按评分择优 → AI 生成人格化评论和 QQ 私信。

## v1.1.4 更新

- 每轮由 AI 按接收会话人设生成一段简短总结，通常80–180字，最多300字。合并相似原因，略过低价值内容，不逐条列候选、标题、BV号或评分；即使候选很多也只发一段。详细审核依据仍保留在面板和日报。零推荐、无新候选、额度耗尽也明确告知本轮结束。
- 聊天消息明确指定主题时，仅本轮搜索及审核使用该主题；未指定则沿用配置关键词。主题只从实际触发消息提取，不读取历史聊天，不改持久配置；下次普通请求、手动或定时仍用配置关键词。配置为空时也可在聊天请求中明确指定主题。
- 保留实时忙闲状态、宿主权限、发送队列和 pending/unknown 判重。预览只生成草稿；关闭 QQ 分享或名单为空时仅保留本地总结。

## v1.1.2 修复

- 修复长时间 AI 审核后控制台地址缓存到期、2 秒探测超时造成的 QQ 私信失败。已验证地址持续复用，连接中断后才重新探测；POST 发送失败不自动重试。
- 面板新增聊天工具实际可用性与 QQ 连接检查；仅启用技能不等于全局工具、媒体分类、单工具开关均允许调用。
- 聊天提示明确优先调用 bili-browse__browse，不用 B 站网页的 412 结果代替插件结果。
- 另一台电脑需要分别导入插件包 bili-scroll-v1.1.4.zip 和技能包 bili-browse-v1.1.4.zip；包内不含配置、Cookie 或投递记录。

## 使用

QQ Agent「插件」页的「刷 B 站」负责定时、筛选、分享与面板；「技能」页新增「聊天逛 B 站」，让模型理解“去逛逛B站”“刷B站”等明确请求并立即启动。面板：http://127.0.0.1:3219/ 。

常用关键词、QQ 白名单、B站 @ 对象仍在配置中填写；也可以说“这轮刷 B 站找 Python 入门”，仅本轮临时使用指定主题，说“去逛逛B站”则照常使用配置关键词。升级保留既有配置与登录。QQ 白名单同时限制聊天发起人，真实身份只读取宿主会话的 trigger[].senderId，拒绝不明、混合作者、自身消息与伪造参数；宿主黑白名单仍是最终边界。

## 筛选与写作

- 先搜索近期候选，整批交给模型淘汰明显无关、低质、营销或不合口味的内容；每条候选必须有明确初筛结论。
- 剩余候选逐条读取完整可用字幕，同时请求 B站 videoshot 原生抽帧拼图，下载后以 image_url 图片 parts 传给模型，不能只给URL文本。CDN不携带登录Cookie。不下载视频、不做本地转写。
- 每视频拼图上限默认3张，可设置1–8张；超出时均匀抽取，明确提供选中拼图编号、网格、时间索引与抽样范围。多P只审第一P。没有字幕、没有拼图、图片不可用或缺少视觉依据时不推荐；字幕超6万字跳过，不静默截断。
- 依宿主 personaForChat 解析当前人设：定时/面板使用全局人设；聊天筛选使用发起会话人设及宿主主人身份覆盖；QQ写作使用接收会话当前人设，同一私聊发起者保留主人覆盖。只读取人设，不读取聊天档案或长期记忆。
- 审完全部候选再按评分选优，默认每轮最多3条，可设置1–10条。不是先达到数量就停止审核。
- 评论与私信正文必须由AI按人格自然写作。QQ完整消息（含标准视频链接）由模型生成；评论仅由程序添加已配置的@对象。没有固定文案、标题UP模板、摘要或程序抽取正文兜底，生成失败便跳过。预览和日报可检查画面依据与两种消息草稿。
- 人设或筛选偏好在审核期间改变时停止投递旧结果；发送前重新校验渠道、名单与宿主权限。旧版只读字幕的待发送记录不再直接投递。

## 触发与额度

定时按配置时间运行，保留30分钟补跑窗口与每日自动额度。手动面板正式运行使用自动额度，预览不占额度、不占正式判重。聊天主动触发不受定时开关和每日自动额度限制，也不消耗自动额度；仍受每轮精选数量、并发锁、联网锁、宿主暂停、白名单与永久发送判重约束。技能立即返回“已开始”，不冒充已完成；每轮结束会生成总结，按 QQ 私聊分享开关发送给白名单，零推荐也通知；当前忙闲状态直接提供给模型，完整结果与回执见面板。

B站评论数量另受现有“每轮最多评论几条”设置控制。两个发送渠道均沿用原设置。接口接受评论不等于公开可见或提醒已到达。

## 发送与数据

QQ沿用宿主 SendQueue 和控制台发送接口。每个视频、每个QQ接收人持久化判重，写网络前先保存pending；pending/unknown不自动重发，避免崩溃或超时造成重复。停止不能撤回已提交请求。

安装目录：resources/app/plugins/bili-scroll 与 resources/app/skills/bili-browse。运行配置由宿主保存，凭证、判重状态、日报位于宿主 data/bili-scroll，不能打包上传。面板仅监听127.0.0.1，校验Host、Origin和请求标记。

## 验证

npm run build；npm test。自动测试使用假发送器。实际模型与B站网络验证使用只预览，不发送真实QQ或评论。

## 安装与源码开发

从本仓库 Releases 下载同一版本的两个 ZIP：在 QQ Agent「插件」页导入 `bili-scroll-v1.1.4.zip`，在「技能」页导入 `bili-browse-v1.1.4.zip`。聊天技能依赖插件提供的能力，需要同时启用。首次使用请在插件配置中填写关键词和 QQ 白名单，在本地面板扫码登录 B 站，先运行预览检查结果，再按需开启发送渠道。

也可将源码中的 `plugins/bili-scroll/` 和 `skills/bili-browse/` 分别复制到 QQ Agent 实际运行目录的 `plugins/` 和 `skills/` 下；桌面安装版通常位于 `resources/app/`。目录内分别包含 `plugin.json` 和 `skill.json`，不要把整个仓库当作一个插件导入。

源码开发需要 Node.js 和 npm，在仓库根目录执行：

```sh
npm ci
npm run build
npm test
```

构建会生成默认插件清单和二维码依赖，安装包已包含这些文件，导入安装包无需 npm。仓库不包含机器专用安装脚本、宿主配置、登录凭证或运行报告。
